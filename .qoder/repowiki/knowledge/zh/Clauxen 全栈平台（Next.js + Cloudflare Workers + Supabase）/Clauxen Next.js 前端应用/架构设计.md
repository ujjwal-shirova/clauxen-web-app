模块按 Next.js App Router 约定划分为两层：
- `src/app/` 服务端路由层：`(main)` 与 `(marketing)` 两个路由组分别承载主应用页面与公开营销站；`api/` 将认证、聊天、计费、沙箱、插件、工作区、文件、任务等后端能力以 REST/流式端点暴露；`auth/`、`cli/`、`gift/claim`、`legal`、`share/[token]` 等独立路径承接跨域认证回调、CLI 设备授权、礼品领取、法律声明与分享页。
- `src/client/` 客户端组件层：由 `contexts/`（auth/auth-gate/chat-session/preferences/artifacts/follow-up）提供全局状态，`hooks/` 封装各域 API 调用，`components/ui/` 原子组件被上层业务组件复用，`components/plugins/`、`components/composer/`、`components/agent/`、`components/checkout-*`、`components/deep-research-*` 等业务视图通过 hooks 与 contexts 消费 `app/api/*` 端点。
- 启动装配在 `src/app/layout.tsx` 中注入全局样式与 providers，`(main)/layout.tsx` 再叠加侧边栏与认证门控，从而让所有业务子模块共享同一外壳。
- 业务数据流统一为：React 组件 → client hooks → fetch/SSE 调用 `app/api/*` route handler → 持久化到 Supabase/Billing Provider，形成单向数据流。
