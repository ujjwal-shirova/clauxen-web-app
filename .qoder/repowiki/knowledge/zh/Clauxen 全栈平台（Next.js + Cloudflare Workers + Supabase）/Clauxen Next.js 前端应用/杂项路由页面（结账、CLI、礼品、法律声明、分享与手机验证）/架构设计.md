所有子目录均遵循 Next.js App Router 约定：每个 URL 段对应一个 `page.tsx`（或 `route.ts` API），页面组件作为服务端组件从 `@/components/*` 引入实际 UI 实现，自身仅负责参数解析、鉴权跳转与 props 透传。
- `checkout/[merchant]/[sessionId]`：通过 `inspectCheckoutSessionToken` 校验 JWT，将 claims 转为 planId / billingCycle / maxTier / returnPath 后交给 `CheckoutSessionClient`。
- `cli/authorize` 与 `cli/device`：CLI 专用 OAuth 入口，先调用 Supabase `getUser()` 校验登录态，未登录则重定向至 `/login?redirectTo=...`；`device/page.tsx` 同样以客户端组件承载设备绑定流程。
- `gift/claim/[token]`：极薄的服务端壳，仅解构 token 并传给 `GiftClaimPageClient`。
- `legal/{cookies,privacy,terms}`：纯静态法律文本页面，无逻辑。
- `share/[token]`：唯一的客户端页面（`"use client"`），动态加载 Cloudflare Turnstile 脚本、调 `/api/v1/share/gate` 获取人机验证配置，再按是否启用 worker 决定走 `/v1/open` 还是 `/api/v1/share/:token/open`。
- `verify-phone`：带 `Metadata.title` 的登录前引导页，包裹 `Suspense` + `AuthLoadingShell`。
- `v1/oauth/hello/route.ts`：暴露 GET 探针供 CLI 预检 OAuth 连通性。
依赖方向单向向外：页面 → `@/components/*` 与 `@/server/*` 工具，不互相引用。
