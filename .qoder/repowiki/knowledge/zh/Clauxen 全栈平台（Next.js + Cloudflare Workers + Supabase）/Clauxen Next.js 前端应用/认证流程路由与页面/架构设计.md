模块按 Next.js App Router 约定组织为两组入口：
- `src/app/auth/` 下的子目录对应服务端 API Route（`route.ts`）或客户端页面（`page.tsx`），分别承载 OAuth 发起 (`oauth/route.ts`)、回调处理 (`callback/route.ts`)、邮箱确认 (`confirm/route.ts`)、Magic Link 设置密码 (`magic/page.tsx`) 和密码重置 (`reset-password/page.tsx`)。
- `src/app/login/` 与 `src/app/signup/` 仅为轻量重定向页，将旧书签与统一后的 `/login` 表单行为对齐。

依赖方向单向向外：服务端 route 通过 `@supabase/ssr` 的 `createServerClient` + 自定义 cookie getter/setter 在请求上下文中读写 Supabase session；公共配置由 `@/utils/supabase/env` 的 `requireSupabaseConfig` 注入；邮箱有效性校验委托给 `@/server/email-verifier/disposable-email`，拒绝一次性邮箱并回退到 `/new?auth=1&error=...`。客户端页面使用 `@/hooks/use-auth`、`@/lib/api/auth`、`@/components/auth/auth-shell` 等共享 UI 组件完成交互。所有对外跳转均经 `safeNext` 白名单校验（仅允许以 `/` 开头且非 `//` 的路径，根路径统一落到 `/new`）。
