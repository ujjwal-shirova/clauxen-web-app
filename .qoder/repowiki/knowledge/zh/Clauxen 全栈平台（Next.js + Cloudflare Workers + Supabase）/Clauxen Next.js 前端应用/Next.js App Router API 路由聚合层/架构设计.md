所有子模块统一采用 Next.js App Router 的文件系统路由约定：每个端点以 `route.ts` 暴露 HTTP handler（如 GET/POST），目录结构直接映射 URL 路径。
- 顶层 `/api/auth` 与 `/api/oauth` 提供传统登录注册与 OIDC 授权码/设备授权等身份协议端点；`/api/v1/auth` 则面向前端 v1 REST 会话体系（魔法链接、OTP、session）。
- `/api/v1/*` 是主业务域：chats、billing、sandbox、plugins、workspaces、files/artifacts/audio、settings/profile/account、projects/library/research/share 以及 internal/scheduled-tasks 等各自独立维护，通过文件系统路径解耦。
- 跨子模块共享的关注点由 Next.js 框架处理：认证状态由 `/api/v1/auth/session` 等端点集中维护，外部回调（razorpay、plugins OAuth callback）统一落在对应 webhook 子路径下，内部调度通过 `/api/internal/scheduled-tasks` 与 `/api/v1/scheduled-tasks` 内外分离。
- 流式响应集中在 `/api/chat/stream` 与 chats 下的生成接口，其余均为 JSON REST 或文件下载。
