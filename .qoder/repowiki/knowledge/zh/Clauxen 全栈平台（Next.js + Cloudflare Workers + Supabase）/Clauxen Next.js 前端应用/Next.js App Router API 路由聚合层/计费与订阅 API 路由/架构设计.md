模块按 Next.js App Router 目录结构组织，每个资源一个 `route.ts` 文件：
- 顶层资源：`plans/`（只读）、`subscription/`（概览 + cancel/resume）、`invoices/`（列表 + `[paymentId]/pdf` 下载）、`address/`（GET/PUT）、`payment-methods/`（含 `setup/verify` 子流程）。
- 支付相关：`checkout-sessions/` 创建会话并派发到 Razorpay；`orders/` 完成支付、Razorpay 回调 (`razorpay-callback`)、UPI 轮询 (`upi/poll`)、QR 码图片 (`upi/qr/[qrId]/image`)、支付校验 (`verify`)。
- 所有处理器统一通过 `@/server/http/api-handler` 的 `withApiHandler` 包装，并以 `requireAuth: true` 强制鉴权；响应由 `@/server/http/api-response` 的 `jsonData` 序列化。
- 业务逻辑下沉至 `@/server/services/billing.service`、`billing-profile.service`、`gift.service`，数据访问走 `@/server/repositories/billing.repository`；客户端输入的 planId/countryCode 等经 `assertCheckoutClaimsMatchClientInput` 与服务端声明核对，确保服务端为权威方。
- 所有路由声明 `runtime = 'nodejs'` 且 `dynamic = 'force-dynamic'`，依赖外部 Razorpay 服务，禁止静态预渲染。
