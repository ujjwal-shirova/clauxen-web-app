基于 Next.js App Router 的路由即 handler 模式：顶层 `route.ts` 处理沙箱列表（GET/POST），`[sandboxId]/route.ts` 处理单个沙箱的 GET/DELETE，其余子目录（commands/connect/files/host/metrics/pause/timeout）各自暴露一个 `route.ts` 作为细分资源端点。

- 所有处理器统一通过 `withApiHandler` / `withApiRouteParams` 包装，先调用 `requireSession(session)` 获取用户，再调用 `assertSandboxOwnedBy(sandboxId, user.id)` 做所有权校验，最后委派给 `@/server/sandbox/sandbox-manager` 中的领域函数（如 `createSandbox`、`runSandboxCommand`、`listSandboxFiles` 等），API 层不持有业务逻辑。
- 响应一律经 `jsonData` 序列化返回；请求体通过 `request.json()` 解析并做类型断言。
- 每个路由文件声明 `runtime = "nodejs"`、`dynamic = "force-dynamic"`，部分长耗时端点（如 commands、top-level POST）额外设置 `maxDuration = 300`。
- 依赖方向单向：本模块 → `@/server/http/*`（认证与响应封装）→ `@/server/sandbox/sandbox-manager`（领域服务）。
