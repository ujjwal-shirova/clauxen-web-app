基于 Next.js App Router 的目录即路由结构，每个认证子功能对应一个 `route.ts`：
- 密码流程：`login/`（dev bypass 模式，带 IP 级速率限制）、`logout/`。
- 无密码流程：`magic/request|complete|inspect/`（5 分钟 magic link）与 `signup/request-otp/` + `verify/`（6 位 OTP）。
- 会话管理：`session/` 同时支持 `GET?quiet=1`（静默刷新）与全量会话解析（从 Supabase JWT claims 或本地 session cookie 重建，并同步 profile）。所有端点统一通过 `@/server/http/api-handler` 的 `withApiHandler` 包装以处理错误与请求元数据，并通过 `@/server/http/api-response` 的 `jsonData` 返回标准化响应体。
- 依赖方向单向向下：本模块仅调用 `@/server/services/*`（identity、auth-email-otp、profile）、`@/server/auth/*`（JWT、session cookie、Supabase claims）、`@/utils/identity-cookie` 以及 `@/lib/profile-names`，不反向被业务逻辑引用；所有 handler 声明 `runtime = "nodejs"` 与 `dynamic = "force-dynamic"` 以保证 Node 运行时可用。
