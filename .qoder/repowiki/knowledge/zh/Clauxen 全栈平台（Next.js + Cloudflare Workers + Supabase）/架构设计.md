仓库以 monorepo 形式组织，顶层 `package.json` 通过 npm scripts 统一编排多运行时构建：
- 运行时边界：`src/` 下的 Next.js App Router 应用（frontend_app + ui_shell_settings + server_core）部署到 Vercel；`cloudflare-workers/` 下的无状态 Worker 通过 `@opennextjs/cloudflare` + `wrangler` 打包并独立部署。
- 共享契约：`src/shared` 提供跨前/后端复用的 Supabase 客户端、API 调用封装、计费/MCP 插件类型等纯函数与 Zod schema，是 frontend_app、server_core 与 tests 共同依赖的单一事实来源。
- 数据层：`supabase/migrations` 用 Supabase CLI 维护时序 SQL 迁移，定义用户、会话、计费、插件、存储桶及 RLS 策略，被 server_core 与 Cloudflare Workers 共同访问。
- 构建链：`scripts/bundle-server-text.mjs` 与 `bundle-research-exports.mjs` 在 `next build` 之前注入服务端文本与 research 导出，`plugins/endpoints` 脚本生成连接器端点供 server_core 使用。
- 测试与文档：`tests/` 覆盖服务端逻辑与 Cloudflare 运行时冒烟用例；`docs/` 记录架构与安全审计；`claude_skills/` 与 `prompts/` 向 Claude Agent 暴露系统工具与工作流模板。
