- 采用 Supabase 标准目录结构：`config.toml` 绑定项目 ID，`migrations/` 下按 `YYYYMMDDHHMMSS_描述.sql` 命名存放单向增量迁移，由 Supabase CLI 按时间戳顺序应用。
- 基础层（`20260506160000_core_backend.sql`）建立扩展（pgcrypto）、公共触发器（`set_updated_at`）、用户表族（`user_settings`、`user_token_balances`）、计费表族（razorpay 订单/支付/事件）、聊天分支状态、上传元数据、速率限制、RLS 策略、私有 storage buckets，以及 `security definer` RPC（token 借贷、支付履约）。
- 后续迁移按主题切分：platform schema/primitives、advisor hardening、realtime 表、billing 扩展、onboarding、chat transcript/keyset pagination、automation queue、connector platform foundation、plugin collections/MCP API keys、OAuth identity、conversation share snapshots、durable deep research 等。
- 安全边界：所有用户可见表通过 `auth.uid()` 施加 RLS；审计类表（如 `razorpay_webhook_events`、`rate_limits`）明确跳过 RLS，仅服务端调用；敏感写操作走 `security definer` 函数。
- 幂等性约定：每个迁移使用 `IF NOT EXISTS`、`DROP POLICY IF EXISTS`、`ON CONFLICT DO NOTHING`、`CREATE OR REPLACE`，可安全重放。
- 依赖方向严格自底向上：早期 migration 定义基础表与 trigger，后期 migration 仅增列、加索引、加 policy、补 seed 或修复，不反向修改基础结构。
