模块按职责分为两层：

- `src/server/auth/` — 会话层。`jwt.ts` 使用 jose 的 `createRemoteJWKSet` 从 Supabase JWKS 拉取公钥（ES256/RS256）并结合可选的 HS256 `SUPABASE_JWT_SECRET` 在进程内校验访问令牌，带 `kid` 回退与 token 级内存缓存；`supabase-session.ts` 暴露 `getSupabaseClaimsFromRequest`，优先解析 `Authorization: Bearer <JWT>`，再回落到 `@supabase/ssr` 的 `sb-<ref>-auth-token` cookie；`session.ts` 聚合多种来源（Supabase JWT、Bearer API Key、OAuth access token、普通 session cookie），通过 `queryOne` 查 `public.profiles` 补齐 displayName/avatar 等展示字段并维护 `userActiveCache` 防已删除用户复用会话；`require-session.ts` 仅提供 `SessionUser | null` → 抛出 `unauthorized` 的守卫。

- `src/server/oauth/` — OAuth2/OIDC 服务层。`service.ts` 定义 `OauthError`、`AuthorizeParams`、`TokenSuccess` 等类型并提供 `createAuthorizationCode`、`issueTokenPair` 等用例，依赖仓库持久化；`repository.ts` 封装对 `oauth_clients / oauth_authorization_requests / oauth_authorization_codes / oauth_consent_grants / oauth_refresh_token_families / oauth_access_tokens` 等表的 SQL 操作；`crypto.ts` 提供 `hashToken`、`generateOpaqueToken`、`generateUserCode`、`verifyPkceS256` 等无状态原语；`redirect.ts` 实现 RFC 8252 loopback URI 校验；`constants.ts` 集中声明 `CLAUXEN_CODE_*`、TTL、token 前缀（`cla_at_` / `cla_rt_` / `cla_ac_` / `cla_dc_`）。依赖方向单向：service → repository + crypto + redirect + constants，auth 层仅通过 `resolveAccessTokenUser` 消费 service 以识别 OAuth 访问令牌。
