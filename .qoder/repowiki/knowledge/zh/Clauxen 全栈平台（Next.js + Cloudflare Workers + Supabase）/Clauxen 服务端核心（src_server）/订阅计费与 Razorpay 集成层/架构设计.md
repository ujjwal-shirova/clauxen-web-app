模块按职责拆分为若干单文件子模块，形成清晰的调用链：
- `checkout-session.ts`：通过 HMAC-SHA256 + base64url 自签 `cs_live_...` 令牌（`mintCheckoutSessionToken` / `inspectCheckoutSessionToken`），承载 planId、billingCycle、currency、seatBreakdown、giftId 等不可信客户端字段，并白名单校验 returnPath。
- `checkout-pricing.ts`：在结账时根据 `CheckoutPlanRow` 与服务端 `plans-catalog` 计算 subtotalPaise，并用 `assertCheckoutClaimsMatchClientInput` 拒绝 DevTools 篡改。
- `razorpay.ts`：统一网关入口。优先经 `billingWorkerRazorpay` 转发到 Cloudflare billing Worker（路径映射 `/v1/orders`→`/v1/razorpay/orders` 等），失败且未配置 `billingRequireWorker` 时回退到 Vercel 直连 `api.razorpay.com`；所有 HTTP 错误统一包装为 `AppError` 带 `razorpay_error` code。
- `billing-worker.ts`：定义 `BillingInvoicePayload` 类型与对 Cloudflare Worker 的通用请求封装，暴露 `generateInvoiceOnWorker`、`fulfillInvoiceOnWorker`（PDF → R2 → Razorpay Documents → 邮件）。
- `invoice.ts`：从 DB 订单行构造权威发票 payload，再交给 worker 渲染 PDF。
- 辅助：`billing-email.ts`、`razorpay-customers.ts`、`razorpay-invoice-upload.ts`、`payment-method-crypto.ts`、`checkout-billing.ts`、`checkout-location.ts`、`checkout-currency-server.ts`、`resolve-razorpay-contact.ts` 分别处理邮箱、客户创建、发票上传、支付方式加密、位置/货币解析等边缘逻辑。
依赖方向单向：业务侧（`checkout-*`）→ `razorpay.ts` → `billing-worker.ts` → 外部服务（Razorpay、Cloudflare Worker、R2、邮件）。
