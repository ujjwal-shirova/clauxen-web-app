模块围绕 "连接器 → 授权 → 工具运行" 三层组织：
- 连接器注册表 `connector-registry.ts` 根据 marketplace 的 `pluginId` 决定走 MCP（远程服务器）还是 REST（Clauxen 自建 toolset），并使用 `connector-endpoints.generated.json` 与 `OVERRIDES` 映射每个提供商的 OAuth provider、scopes 及 fallback。
- 授权链路集中在 `plugin-connect.ts`，通过 `oauth-discovery.ts` 实现 RFC 9728 动态发现（authorization server / protected resource / dynamic client registration），再由 `oauth-providers.ts` 提供 Google/GitHub/Slack/Microsoft 预注册客户端配置；`token-manager.ts` + `token-crypto.ts` 负责 access token 的加密封装与持久化。
- 运行时暴露两类工具给 agent：MCP 工具经 `mcp-client.ts` 调用远端 MCP server；REST 工具由 `rest-toolsets.ts` 以 typed schema + `run(api, args)` 形式定义 Google Drive / Outlook / OneDrive / Teams / SharePoint 等 first-party API 调用。
- 所有工具调用统一经过 `plugin-firewall.ts` 的参数大小限制、凭据外泄检测、按用户/风险等级的 rate limit、以及不可见字符剥离、HTML/脚本清洗、指令注入匹配、敏感信息 redact 和 `[UNTRUSTED]` 标记；`plugin-runtime.ts` 把 catalog 中的工具暴露为 `mcp__<slug>__<tool>` 名称，并内置 `search_tools` / `call_tool` 两个元工具供模型在超过 48 个直接工具时检索。
- 依赖方向单向：runtime → firewall/mcp-client/rest-toolsets/token-manager → connect/oauth-discovery/oauth-providers/connector-registry → repositories；UI 侧仅通过 `/api/v1/plugins/callback`、`/api/v1/plugins/oauth-client` 等 REST 端点交互。
