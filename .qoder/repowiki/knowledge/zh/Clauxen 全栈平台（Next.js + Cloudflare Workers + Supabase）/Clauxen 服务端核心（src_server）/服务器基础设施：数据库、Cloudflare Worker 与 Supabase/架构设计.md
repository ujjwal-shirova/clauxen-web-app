模块按三个并列子域组织，依赖方向单向向外（业务层 → infrastructure）：
- `src/server/db/`：基于 `pg.Pool` 的连接池与查询封装。`pool.ts` 通过 `cloudflareContext()` 判断是否运行在 Cloudflare Hyperdrive 下——Hyperdrive 路径使用 per-request 的小连接池并由 `requestResource` 管理生命周期；非 Hyperdrive 路径维护一个全局单例 Pool，并针对 Vercel Fluid compute 将 Supabase 直连 URL 规范化为 IPv4 事务池器地址。
- `src/server/cloudflare/`：Worker 运行时适配层。`context.ts` 安全获取 OpenNext 的 Cloudflare context；`request-resources.ts` 基于 `AsyncLocalStorage` 实现 invocation-scoped 的资源注册与释放；`generation-queue.ts` 消费队列消息并以内部 token 调用 `/api/v1/internal/*`；`storage-access.ts`、`service-fetch.ts`、`chat-configuration.ts`、`types.d.ts` 分别封装 KV/R2/服务间调用与类型定义。
- `src/server/infrastructure/supabase/server.ts`：Supabase 客户端工厂，导出 `getSupabaseAdmin()` 与 `getSupabaseAnonServerClient()` 两个模块级单例，并通过 `getUserFromAccessToken` 校验访问令牌。

模块内分层清晰：db 层依赖 cloudflare 层的 context/request-resources；supabase 层独立不反向依赖 db。
