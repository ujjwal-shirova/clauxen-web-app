模块按职责划分为三个子目录：
- `src/server/http/`：请求处理核心。`api-handler.ts` 定义 `ApiHandler` 类型与 `withApiHandler` 高阶函数，封装数据库连接（`withDatabaseRequest`）、会话解析（`getSessionFromRequest`）、可选的 `requireAuth` / `requireChatAuth` 鉴权检查、`REQUEST_ID_HEADER` 注入和 `Server-Timing` 性能头；`route-params.ts` 在其之上再包装一层 `withApiRoute` / `withApiRouteParams` 以适配 Next.js Route Handlers 的 `(request, context)` 签名并注入 `params`；`api-response.ts` 统一成功 (`jsonData`) 与错误 (`jsonError`) 响应格式，并在生产环境隐藏堆栈；其余文件按横切关注点拆分为独立中间件：`rate-limit.ts` + `durable-rate-limit.ts`（基于 Cloudflare Durable Object 的全局限速）、`internal-generations-auth.ts` / `internal-scheduled-tasks-auth.ts`（内部 Worker 调用共享密钥校验）、`chat-id.ts` / `share-privacy.ts` / `request-meta.ts` 等。
- `src/server/config/`：集中式环境变量入口。`env.ts` 通过 `optional` / `firstOptional` 从 `process.env` 及 Vercel Secrets 中解析所有运行时常量（模型名、API Key、Razorpay、Cloudflare R2、Worker URL 等），并暴露 `isProduction` / `isVercel` 标志；`cloudflare-perf-profile.ts` 仅作为部署文档与 Cloudflare 优化参数的单一事实来源；`edge-flags.ts` 暴露边缘侧特性开关。
- `src/server/cookies/`：Cookie 编解码与 consent/visitorId/advertisingId/UTM 属性的读取与写入，依赖 `@/lib/cookie-consent` 中的常量与解析器，并通过 `cookieBase` 根据协议或 `env.isVercel` 自动选择 `secure`。
依赖方向：`http/*` → `config/env`、`auth/session`、`db/errors`、`db/pool`；`cookies/http` → `config/env` 与 `lib/cookie-consent`；`config/*` 不反向依赖业务代码。
