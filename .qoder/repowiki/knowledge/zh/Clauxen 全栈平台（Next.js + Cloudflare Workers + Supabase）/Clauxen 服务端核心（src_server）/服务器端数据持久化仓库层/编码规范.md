- 每个仓库文件按领域拆分（chats、messages、profile 等），导出若干命名良好的 async 函数并配套 Row/Input 类型别名。
- 所有 SQL 通过 `query` / `queryOne<T>()` 执行，表名统一带 `public.` 前缀，列列表用常量字符串（如 `PROFILE_COLUMNS`、`JOB_COLUMNS`）集中声明以避免重复。
- 更新接口采用 patch 语义：可选字段经 `coalesce($n, column)` 或 `case when $n is not null then $n else column end` 实现选择性覆盖，未提供的字段保持不变。
- 对不可信输入做严格过滤后再拼入 LIKE 查询（如 `escapeLike` 转义 `%_\`），并通过 `limit` + clamp 防止过大偏移量。
- 易冲突的写路径（如 `createChatFast`、`allocateUniqueChatId`）采用重试循环并在捕获到 `AppError` 且 code 为 `conflict` 时继续尝试。
