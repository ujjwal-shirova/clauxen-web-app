单入口 Worker（`src/index.ts`），通过 Wrangler 配置 (`wrangler.toml`) 注册为每分钟触发的 Cron、Queue Producer 与 Consumer。
- HTTP 层：暴露 `/health` 与受 `SCHEDULED_TASKS_INTERNAL_TOKEN` + `x-clauxen-internal` 双重鉴权保护的 `/v1/dispatch` POST；由 `isInternalRequest` 使用常量时间比较防止时序攻击。
- 调度链路：Cron → `dispatch()` 调用上游 `APP_ORIGIN/api/v1/internal/scheduled-tasks/dispatch`（经 `appFetch` 走 Cloudflare Private Service Binding `APP` 或回退到公网 `fetch`）→ 将返回的 `AutomationJob[]` 批量推入 `AUTOMATION_QUEUE`。
- 消费链路：`queue(batch)` 逐个调用 `/api/v1/internal/scheduled-tasks/execute`，根据响应状态码决定 `ack()`、`retry({ delaySeconds })` 或进入 DLQ（`clauxen-automation-runs-dlq`）。
- 可靠性：依赖下游 Supabase 侧基于 `execution_key/run` 租约的去重语义，Worker 仅保证 at-least-once 投递与有限重试（max_retries=5, retry_delay=60s）。
- 边界：对外只暴露健康检查与内部调度入口，所有业务请求均通过内部 Token 鉴权后转发给宿主应用。
