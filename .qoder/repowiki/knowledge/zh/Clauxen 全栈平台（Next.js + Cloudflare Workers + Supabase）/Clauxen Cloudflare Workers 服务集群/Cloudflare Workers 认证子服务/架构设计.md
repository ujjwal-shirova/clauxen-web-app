模块包含三个相互独立的 Wrangler Worker，各自有独立的 `wrangler.jsonc`/`wrangler.app.jsonc`、`tsconfig.json` 和入口 `src/index.ts`：
- `workers/auth-email/`：单文件 Worker (`src/index.ts`)，通过 KV 存储 OTP hash、一次性 signup ticket 和 magic link，调用 Cloudflare Email Service 发送验证码或含 5 分钟 TTL 的魔法链接；内部鉴权依赖 `Authorization: Bearer <AUTH_EMAIL_INTERNAL_TOKEN>` 或 `x-clauxen-internal` 头。
- `workers/native-auth/`：入口仅转发到 `gateway.ts` 中的 `handleNativeAuth`，对 `/api/v1/auth/native/*` 端点进行参数校验、JSON body 限流、Origin 白名单和 CF IP 速率限制后，以 GoTrue/SUPABASE_PUBLISHABLE_KEY 身份透传到上游 Supabase，并在 `github/gitlab` authorize 时做 302 重定向到 `auth.clauxen.com`。
- `workers/oauth-broker/`：入口在 `index.ts` 中拦截 `clauxen.com/auth/oauth` 并将指向 Supabase 的 authorize 请求重写到本 Worker；核心逻辑在 `broker.ts`，实现 RFC 6749 风格的 authorization_code + PKCE 流程，通过注入的 `BrokerDependencies`（credentials、flow store、canonicalEmail、fetcher）解耦；状态机由 `OAuthFlow` Durable Object (`flow.ts`) 用 SQL 表维护 pending→verifying→code→token 四阶段，并通过 alarm 清理过期记录；第三方提供方对接集中在 `providers.ts`，当前支持 GitHub 与 GitLab。
依赖方向：`oauth-broker` 依赖 Supabase 作为最终 token issuer 和 identity lookup（Hyperdrive 连接），`native-auth` 依赖 Supabase GoTrue，两者均不直接持有用户凭据。
